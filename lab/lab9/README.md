# Лабораторна робота №9 — Акустична варта

Standalone-застосунок Angular 22 з одним основним компонентом. Початкові три датчики з методички: Центр (72 дБ), Сихів (58 дБ), Левандівка (45 дБ). Реалізовано додавання, видалення та перемикання active / inactive.

Дані знаходяться в масиві компонента. Після перезавантаження сторінки повертаються початкові три датчики. MockAPI, localStorage, маршрутизація, backend і SSR у цій роботі не використовуються. RxJS є стандартною залежністю Angular, власного коду з RxJS немає.

Проєкт уже налаштовано. Повторно виконувати `ng new` поверх цих файлів не потрібно.

## 2. Встановлення і запуск

Відкрий термінал саме в папці `lab9`, де знаходиться `package.json`.
Якщо термінал зараз у корені `Web_Programming`, виконай:

```powershell
cd lab\lab9
node -v
npm -v
npm install
npx ng version
npm start
```

Відкрий [http://localhost:4200](http://localhost:4200).

Команда `npm start` виконує `ng serve`. Для Angular-застосунку Live Server не потрібен. Не відкривай вихідний `src/index.html` подвійним натисканням.

Локальний Angular CLI встановлюється з залежностями; `npx ng` запускає саме його. Якщо викладач окремо просить глобальний CLI, можна встановити `npm install -g @angular/cli@22`.

Сумісний Node.js: 22.22.3+ у гілці 22, 24.15.0+ у гілці 24 або гілка 26. TypeScript — 6.0.x. Поточна перевірена версія Node.js на цьому комп’ютері — 26.13.0.

Після `npm install` з’являться `node_modules` і `package-lock.json`. `package-lock.json` додай до Git, а `node_modules` — ні.

## 3. Перевірка дій

1. Переконайся, що є три початкові картки; Левандівка має статус inactive.
2. Додай «Сенсор Підзамче», район «Шевченківський», шум 65. Має з’явитися четверта картка зі статусом active.
3. На новій картці натисни «Змінити статус»: з’явиться inactive та сіре оформлення. Повторне натискання поверне active.
4. Натисни «Видалити» на цій картці: вона зникне, знову залишаться три датчики.
5. Спробуй додати датчик без назви чи з від’ємним шумом: з’явиться повідомлення, картка не додасться. Значення 0 дБ є допустимим.
6. Після видалення всіх датчиків буде показано повідомлення «Датчиків поки немає».
7. Перезавантаж сторінку: знову з’являться початкові три датчики.

## 4. Production build

У другому терміналі в папці `lab9` виконай:

```powershell
npm run build
```

Результат має з’явитися у `dist/acoustic-watch/browser/`: `index.html`, `main-….js`, `styles-….css` та інші файли збірки.

Перевір production-версію через HTTP:

```powershell
npm run preview
```

Ця команда запускає `npx http-server dist/acoustic-watch/browser -c-1`. Якщо npx запропонує встановити http-server, погодься. Відкрий адресу з термінала, зазвичай [http://127.0.0.1:8080](http://127.0.0.1:8080).

Папка `dist` створюється справжньою Angular-збіркою. У вихідному архіві її немає: у середовищі підготовки було недоступне завантаження Angular із npm. Результат `ng build` потрібно перевірити після `npm install` на твоєму комп’ютері.

## 5. GitHub Pages у наявному репозиторії

Найпростіше використати той самий спосіб публікації, що й для попередніх лабораторних. Якщо Pages уже працює з гілки `main`, папки `/ (root)`:

1. Виконай `npm run build`.
2. Додай до Git папку `lab/lab9`, включно з `src`, `dist` і `package-lock.json`.
3. Перевір, що `dist/acoustic-watch/browser/index.html` справді потрапив до коміту. Якщо кореневий `.gitignore` ігнорує dist, додай виняток `!lab/lab9/dist/` після правила ігнорування.
4. Завантаж зміни на GitHub звичним способом.
5. Після завершення публікації відкрий:

[https://vrekunov2023.github.io/Web_Programming/lab/lab9/dist/acoustic-watch/browser/](https://vrekunov2023.github.io/Web_Programming/lab/lab9/dist/acoustic-watch/browser/)

У `angular.json` задано `baseHref: "./"`, щоб JS і CSS завантажувалися з поточної папки як локально, так і в підпапці GitHub Pages.

Методичка описує два варіанти: зберігати dist у Git або створювати його через Actions. Для твого наявного сайту перший варіант потребує менше змін.

### Додатковий варіант: GitHub Actions

У `.github/workflows/deploy.yml` цієї лабораторної є готовий шаблон для твого репозиторію. Оскільки він лежить усередині `lab/lab9`, GitHub його автоматично не запускає.

Для переходу на Actions скопіюй шаблон у кореневу `.github/workflows/deploy.yml` репозиторію та вибери Settings → Pages → Source → GitHub Actions. Якщо кореневий workflow уже існує, спочатку узгодь його вміст; не замінюй наосліп.

Шаблон збирає Angular із `lab/lab9` і публікує весь сайт репозиторію разом із попередніми лабораторними та головною сторінкою звітів. Не додавай другий конкуруючий workflow публікації Pages.

## 7. Скриншоти для звіту

1. Результат `npx ng version` — версії CLI, Angular, Node.js.
2. Сторінка з трьома початковими датчиками.
3. Доданий «Сенсор Підзамче» зі зміненим статусом inactive.
4. Список після видалення доданого датчика.
5. Успішний `npm run build`, розгорнута папка `dist/acoustic-watch/browser` і відкритий її `index.html` у редакторі. Можна зробити один спільний скриншот або кілька окремих.
6. Production-сторінка через локальний HTTP-сервер; залиш видимою адресу браузера.
7. Сторінка на GitHub Pages після фактичної публікації.

Звіт і відповіді на дев’ять контрольних запитань підготуємо після перевірки запуску та збірки, щоб описати фактичний результат.
