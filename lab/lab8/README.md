# Лабораторна робота №8

Робота з даними з API на TypeScript. Продовження «Акустичної варти» з лабораторної №7 зі збереженням оформлення, фільтрів та обробки помилок.

## Що змінилося

- `src/sensors.ts` — вихідний код на TypeScript.
- `interface Sensor` описує поля `id`, `name`, `district`, `noiseLevel` і `status`.
- `status` має тип `'active' | 'inactive'`; список даних має тип `Sensor[]`.
- `loadSensors(): Promise<void>` завантажує дані з чинного MockAPI.
- `renderSensors(sensorArray: Sensor[]): void` створює картки.
- DOM-елементи типізовано через `querySelector<HTMLDivElement>()`, `HTMLSelectElement` та `HTMLInputElement`. Наявність елементів перевіряється перед використанням.
- `tsconfig.json` вмикає `strict`, задає `rootDir: ./src` та `outDir: ./dist`.
- `dist/sensors.js` згенерований справжнім компілятором TypeScript 6.0.3. Саме цей файл підключено до `index.html` як модуль.
- Контейнер має `id="sensors"`, як у методичці.

API використовується той самий:

https://6b057043db01cf4636088933.mockapi.io/api/v1/sensors

Заново створювати MockAPI або заповнювати дані не потрібно. Якщо в попередній роботі рівень «Сенсор Центр» змінено на 75 дБ, сторінка покаже актуальні 75 дБ із сервера.

## Запуск та компіляція

1. Розпакуйте папку `lab8` у `Web_Programming/lab`.
2. Відкрийте термінал саме в папці `lab8`.
3. Виконайте:

```powershell
npm install
npm run build
```

Команда `npm run build` виконує `tsc`: читає `src/sensors.ts` і створює `dist/sensors.js`. Якщо компіляція успішна, `tsc` зазвичай не виводить повідомлень про результат.

Відкрийте `index.html` через Live Server. Згенерований `dist/sensors.js` уже є в архіві, тому початковий перегляд сторінки можливий і до встановлення пакетів. Для редагування та повторної компіляції потрібен TypeScript.

Під час редагування:

```powershell
npm run watch
```

Лише перевірка типів без створення файлів:

```powershell
npm run check
```

Змінюйте код у `src/sensors.ts`. Після змін запускайте компіляцію; вручну редагувати `dist/sensors.js` не потрібно.

## Перевірка типів

Щоб побачити користь інтерфейсу, тимчасово додайте перед `loadSensors();`:

```ts
const example: Sensor = {
  id: 'test',
  name: 'Тестовий сенсор',
  district: 'Галицький',
  noiseLevel: '75',
  status: 'normal'
};
```

`npm run check` має показати помилки: рядок `'75'` не відповідає `number`, а `'normal'` не входить до `'active' | 'inactive'`. Після перевірки видаліть цей приклад і повторіть `npm run build`.

Інтерфейс TypeScript не перевіряє JSON під час виконання. У коді додатково збережено перевірку даних через `isSensor()`, тому некоректна структура з сервера потрапляє в обробку помилки.

## Перевірка сторінки

- На сторінці видно сенсори з назвами, районами, рівнями шуму та станами active/inactive.
- У Network є успішний GET-запит sensors.
- В HTML підключено `./dist/sensors.js`, а не `.ts` і не старий `js/app.js`.
- Фільтри за районом і критичним шумом працюють разом.
- Після зміни даних у MockAPI й перезавантаження сторінки показуються нові значення.

Під час підготовки виконано сувору компіляцію TypeScript і перевірки з підміненою відповіддю fetch. Новий живий запит та візуальний вигляд lab8 потрібно підтвердити після запуску у браузері.

## Для звіту

Збережіть скриншоти:

1. `interface Sensor` та типізовані функції в `src/sensors.ts`.
2. Успішна команда `npm run build` і наявність `dist/sensors.js` у структурі папок.
3. Сторінка з картками та GET-запит sensors зі статусом 200 у Network.

У репозиторій завантажуйте `src`, `dist`, `tsconfig.json`, `package.json` і створений npm файл `package-lock.json`. `node_modules` уже виключено через `.gitignore`.
