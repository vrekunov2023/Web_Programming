# Лабораторна робота №6

## Відображення та фільтрація сенсорів у DOM

Продовження проєкту «Акустична варта» з лабораторної №5. Після «Поточного моніторингу» додано секцію «Активні сенсори». Вона показує шість сенсорів Львова та дозволяє одночасно фільтрувати їх за районом і критичним статусом.

## Запуск

Відкрийте папку `lab6` у VS Code та запустіть `index.html` через Live Server. Або відкрийте термінал у папці `lab6`, виконайте `python -m http.server 8000` і перейдіть на http://localhost:8000.

Для роботи імпортів JavaScript потрібен HTTP-сервер. Подвійний клік по HTML-файлу може заблокувати модулі через правила браузера.

CSS уже підготовлено. Встановлення залежностей для перегляду не потрібне. Для подальшого редагування SCSS можна виконати `npm install`, потім `npm run build` або `npm run sass`.

## Зміни

- `index.html`: нова секція, список районів, checkbox та порожній контейнер `.sensor-list`. Секцію «Датчики мережі» замінено на нову, щоб не дублювати картки.
- `js/app.js`: дані, пошук елементів через `querySelector()`, функції `createSensorCard()`, `renderSensors()` і `applyFilters()`, обробники `change`.
- `scss/_active-sensors.scss`: оформлення секції, адаптивної сітки, фільтрів та трьох статусів.
- `scss/main.scss`: підключення нового SCSS-модуля.
- `css/main.css`: готові стилі для браузера.

Використано наявні `NoiseSensor` і `MonitoringSystem`. Статус отримується методом `getStatus()`, тому правила не дублюються в коді фільтрів. Пороги з лабораторної №5: до 55 дБ включно — normal, від 55 до 70 дБ включно — warning, понад 70 дБ — critical. Це навчальні межі проєкту.

На зразку NS-05 має 71 дБ і warning. У цій версії для NS-05 встановлено 69 дБ, щоб зберегти warning відповідно до правил наявного класу. Інші значення й адреси відповідають зразку.

Під час початкового завантаження відображаються всі шість карток. Фільтри автоматично застосовуються після зміни. Якщо збігів немає, контейнер залишається порожнім. Додавання або видалення сенсорів, таймери й localStorage не реалізовувалися.

## Перевірка вручну

1. Відкрийте сторінку: має бути шість карток, по дві кожного статусу.
2. Виберіть «Галицький»: залишиться NS-01.
3. Виберіть «Усі райони»: знову буде шість карток.
4. Увімкніть «Тільки критичні»: залишаться NS-03 та NS-06.
5. З увімкненим checkbox виберіть «Шевченківський»: залишиться NS-03.
6. З увімкненим checkbox виберіть «Галицький»: список буде порожній.
7. Вимкніть checkbox: повернеться NS-01.
8. Перевірте вузьке вікно: картки розташовуються в одну колонку.

## Контрольні питання

1. **Для чого використовується `document.querySelector()`?** Повертає перший елемент, який відповідає CSS-селектору. Якщо елемента немає, повертає `null`.
2. **Що робить `document.createElement()`?** Створює новий HTML-елемент. Для появи на сторінці його потрібно додати до DOM, наприклад через `append()`.
3. **Для чого потрібна властивість `textContent`?** Читає або задає текст елемента. Переданий текст не обробляється як HTML.
4. **Навіщо очищувати `.sensor-list` перед повторним відображенням?** Щоб попередні картки не дублювалися й не залишалися після зміни фільтрів. У роботі використано `replaceChildren()`.
5. **Що повертає метод `filter()`?** Новий масив з елементами, для яких функція перевірки повернула істинне значення. Початковий масив не змінюється.
6. **Як отримати вибране значення з `select`?** Прочитати властивість `districtFilter.value`.
7. **Як перевірити, чи checkbox увімкнений?** Прочитати булеву властивість `criticalFilter.checked`.
8. **Чому після зміни фільтра потрібно знову викликати `renderSensors()`?** Зміна масиву сама не оновлює DOM. Функція очищує контейнер і додає картки, які відповідають поточним умовам.

## Висновок

Під час роботи реалізовано створення карток сенсорів засобами DOM та фільтрацію масиву методом `filter()`. Отримано практичні навички використання `querySelector()`, `createElement()`, `textContent`, `classList`, `append()`, `replaceChildren()` та `addEventListener()`. Фільтри за районом і критичним статусом працюють одночасно, а оформлення карток залежить від статусу сенсора.
